# Validation 1.4.2 — variantes simulées Chef d’équipe et Admin Maison

Ce document définit la campagne reproductible du lot intermédiaire **1.4.2**. Il valide uniquement l’ajout des variantes simulées **Chef d’équipe** et **Admin Maison** au sélecteur local de `/projet`, leur séparation effective des outils interdits et la non-régression des variantes Sound Designer et Réviseur.

Le lot **1.4.1** reste acquis selon son [protocole historique](1.4-role-variants.md). Le lot 1.4.2 reste **en attente de validation humaine** tant que la présente campagne n’a pas reçu de décision. Cette campagne ne valide ni la sous-étape 1.4 complète, ni la phase 1, ni le démarrage du lot 1.4.3 ou de la sous-étape 2.1.

## Livraison à identifier

Avant toute conclusion, consigner :

- la branche testée ;
- le SHA complet du commit ;
- l’URL de la pull request ;
- Google Chrome et les dimensions de viewport utilisées ;
- la date, le système d’exploitation et l’identité du validateur.

Une modification postérieure au SHA consigné impose de rejouer les contrôles concernés.

## Périmètre du lot

Le lot couvre :

- quatre choix de rôle simulé : Sound Designer, Réviseur, Chef d’équipe et Admin Maison ;
- Sound Designer comme état initial après chargement et nouvelle entrée dans `/projet` ;
- une bascule purement locale, non persistante, sans changement d’URL ni ajout dans l’historique du navigateur ;
- un arbre Chef d’équipe centré sur tableau de bord, progression, livre, simulation, historique, commentaires, validation finale et préparation de la publication dans Jacques ;
- trois axes de progression distincts : Doublage, Révision fondée sur les validations obtenues et attendues, et état textuel de Validation finale ;
- un arbre Admin Maison centré sur membres, équipes, invitations, projets, permissions et audit ;
- l’absence réelle dans le DOM des outils interdits pour chaque rôle ;
- le nettoyage des simulations, historiques et tiroirs lors du démontage de leur workspace ;
- le rendu Chrome à `1440 × 1000` et `768 × 1024` ;
- la navigation clavier, le focus visible, les libellés accessibles, l’unicité du `h1` et l’absence de débordement horizontal.

Le lot n’ajoute aucune authentification, permission réelle, identité de phase 2, persistance, donnée distante, modification audio, gestion effective de membres ou invitations, validation, rejet, publication ou dépublication. Toutes les données de management et toutes les formulations d’action sont fictives, locales et non exécutoires.

## Préconditions

- Node.js 24 ou plus récent ;
- pnpm 11.19.0 via Corepack ;
- Google Chrome disponible pour Playwright ;
- dépôt positionné sur le SHA à valider ;
- dépendances installées depuis le lockfile ;
- aucun service distant requis.

```powershell
corepack pnpm install --frozen-lockfile
```

Le dossier local non versionné `EPUB tests/`, s’il est présent, doit rester hors index et strictement inchangé.

## Contrôles automatiques obligatoires

Depuis la racine du dépôt, sur le SHA à valider :

```powershell
corepack pnpm validate
corepack pnpm test:e2e
$mergeBase = git merge-base HEAD origin/main
git diff --check "$mergeBase..HEAD"
git status --short
```

Résultat attendu : toutes les vérifications TypeScript, ESLint, Vitest et Playwright réussissent ; les deux projets Chrome passent sans erreur console ni erreur page ; le diff ne contient aucune erreur d’espace ; le statut Git ne révèle aucune modification inattendue en dehors du dossier local `EPUB tests/`.

## Contrôles fonctionnels obligatoires

### 1. Sélecteur et état initial

1. Ouvrir directement `/projet`.
2. Vérifier la présence des quatre choix.
3. Vérifier que Sound Designer est le seul choix annoncé actif avec `aria-pressed="true"`.
4. Recharger la page, puis quitter et entrer de nouveau dans `/projet`.

Résultat attendu : Sound Designer redevient actif ; aucun choix n’est persisté.

### 2. Variante Chef d’équipe

Activer Chef d’équipe et vérifier les régions suivantes :

- Tableau de bord ;
- Progression ;
- Livre ;
- Simulation/Navigation ;
- Historique ;
- Commentaires ;
- Validation finale ;
- Préparation de la publication.

Résultat attendu : le contexte d’en-tête annonce Chef d’équipe, un seul `h1` est présent, le livre et la simulation restent consultables et les décisions affichées sont explicitement fictives ou non exécutoires.

### 3. Progression séparée

Dans la région Progression, vérifier séparément :

- Doublage avec chapitres terminés et total ;
- Révision avec validations obtenues et attendues ;
- Validation finale avec un état textuel prévu par le produit.

Résultat attendu : aucun pourcentage global unique ne remplace ces trois axes.

### 4. Interdictions Chef d’équipe

Inspecter le DOM et l’arbre d’accessibilité.

Résultat attendu : aucune bibliothèque audio, aucun sélecteur de fichier local, aucun inspecteur audio, aucune commande de montage et aucune action de dépublication ne sont montés. Jaquette désigne l’outil de production et Jacques la destination de publication.

### 5. Variante Admin Maison

Activer Admin Maison et vérifier les régions suivantes :

- Membres ;
- Équipes ;
- Invitations ;
- Projets ;
- Permissions ;
- Audit.

Résultat attendu : les données sont manifestement fictives et locales ; les aperçus n’effectuent aucune gestion réelle.

### 6. Interdictions Admin Maison

Inspecter le DOM et l’arbre d’accessibilité.

Résultat attendu : aucune bibliothèque audio, aucun sélecteur de fichier local, aucun inspecteur audio, aucune commande de montage, aucun outil de validation Réviseur, aucune validation finale et aucune préparation de publication Chef d’équipe ne sont montés.

### 7. Bascule, navigation et nettoyage

1. Démarrer une simulation et ouvrir l’historique dans un workspace qui les propose.
2. Parcourir les quatre rôles deux fois.
3. Observer le focus, l’URL, la longueur de l’historique du navigateur et un marqueur JavaScript conservé en mémoire.

Résultat attendu : un seul arbre de rôle est monté à la fois ; simulation, historique et tiroirs démontés ne fuient pas ; le focus reste visible ; l’URL, l’historique et le marqueur ne changent pas.

### 8. Responsive et accessibilité

Aux formats `1440 × 1000` et `768 × 1024` :

- vérifier la lisibilité des quatre choix de rôle ;
- vérifier l’ordre logique des régions ;
- faire défiler les workspaces pour atteindre chaque région ;
- vérifier l’absence de libellé tronqué, chevauchement ou débordement horizontal ;
- parcourir le sélecteur au clavier et activer un rôle avec `Espace` ;
- vérifier qu’un seul `h1` est présent.
